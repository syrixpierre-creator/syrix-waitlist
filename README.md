# SYRIX Waitlist

Waitlist site for **SYRIX CHAT** (all-in-one messenger) and **WhaRise** (reactions for WhatsApp channel posts), by Syrix Vision Company.
English by default, French with the EN/FR switch or `?lang=fr`.

*Site de liste d'attente pour SYRIX CHAT et WhaRise. Anglais par défaut, français via le bouton EN/FR ou `?lang=fr`. Résumé en français plus bas.*

## Features

- Motion-design landing page (React 19, Vite, Motion): kinetic headline, live chat and channel-reaction illustrations, the SYRIX CHAT promo video, an auto-playing WhaRise walkthrough, scroll reveals, marquee, FAQ. Respects `prefers-reduced-motion`.
- Real signups: `POST /api/waitlist` stores each e-mail once per product and returns the real position in line. No invented counters.
- Anti-abuse: e-mail validation, honeypot field, per-IP rate limit (8 requests / 10 min), 8 KB body limit.
- Admin: `GET /api/admin/stats` (counts per product) and `GET /api/admin/export.csv`, with `Authorization: Bearer <ADMIN_TOKEN>` or `?token=`.
- Optional confirmation e-mail in the visitor's language when `SMTP_HOST` is set.
- Storage: MongoDB (`MONGODB_URI`), e.g. a free MongoDB Atlas cluster. Without it (development only) signups stay in memory.

## Run locally

```bash
npm install
cp .env.example .env              # set MONGODB_URI and ADMIN_TOKEN
npm run build && node --env-file=.env server/index.mjs   # http://localhost:8080
npm test                          # API tests (in-memory; TEST_MONGODB_URI=... to run them on MongoDB)
```

Development with hot reload: `npm run dev` (Vite on :5173, API on :8080).

## Deploy on Render

1. **MongoDB Atlas** (free M0 cluster): create a cluster, a database user, and in *Network Access* allow `0.0.0.0/0` (Render free services have no fixed IP). Copy the connection string from *Connect > Drivers*, e.g. `mongodb+srv://user:password@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority`.
2. **Render**: *New > Blueprint*, pick this repository. `render.yaml` creates the web service (`npm ci --include=dev && npm run build`, `npm start`, health check `/api/health`).
3. When asked, paste `MONGODB_URI`. `ADMIN_TOKEN` is generated by Render (see *Environment*). SMTP variables are optional.
4. **Domain**: in the service, *Settings > Custom Domains*, add `syrixz.com` and `www.syrixz.com`, then create the DNS records Render shows. HTTPS is automatic.

The free plan sleeps after 15 minutes without traffic; the first visit after that takes a few seconds. Use a paid instance to keep it awake.

## Self-host (Docker)

```bash
cp .env.example .env   # set ADMIN_TOKEN
docker compose up -d --build   # site on 127.0.0.1:8080, MongoDB in the waitlist-mongo volume
```

## Export the list

```bash
curl -H "Authorization: Bearer $ADMIN_TOKEN" https://syrixz.com/api/admin/export.csv -o waitlist.csv
curl -H "Authorization: Bearer $ADMIN_TOKEN" https://syrixz.com/api/admin/stats
```

## Résumé (FR)

- Base de données : MongoDB (`MONGODB_URI`), par exemple un cluster gratuit MongoDB Atlas.
- Déploiement Render : *New > Blueprint* sur ce dépôt, coller `MONGODB_URI`, puis ajouter `syrixz.com` dans *Custom Domains*. `ADMIN_TOKEN` est généré par Render.
- Dans Atlas, *Network Access* doit autoriser `0.0.0.0/0` (pas d'IP fixe sur l'offre gratuite de Render).
- Les inscriptions sont réelles : chaque e-mail est enregistré une fois par appli, avec sa vraie position.
- Export : `/api/admin/export.csv` avec le jeton `ADMIN_TOKEN`.
- WhaRise envoie des réactions automatiquement ; la FAQ du site le dit clairement, car une activité automatisée peut aller contre les conditions de WhatsApp.
